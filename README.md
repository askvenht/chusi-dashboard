# 初司运营账号数据面板（本机开发版）

## 当前状态（2026-11-19，经真实账号实测）
- **小红书已打通**：在面板添加小红书账号会打开该账号专用的 Chrome（独立资料目录 `data/profiles/<账号ID>`）。扫码后，面板从这个窗口读取平台本人身份（userId、昵称、小红书号），**自动绑定**到对应卡片，然后自动采集一次；之后可以随时点“采集最新数据”。
- 实测账号：实测小红书账号已自动绑定（昵称、小红书号见本机面板）。写入近 30 天（2026-10-20 至 2026-11-18）× 6 项指标，共 180 条，粉丝总数 11。近 7 天的合计与小红书页面显示一致：创作中心首页显示“曝光数 2,363、观看数 297、净涨粉 1”，账号概览页显示“点赞 4、笔记涨粉 2、发文活跃度 5”。日期归属也用笔记的实际发布时间核对过。面板界面的完整流程实测通过：关闭窗口 → 登录此账号 → 自动核验 → 自动采集，约 10 秒。
- **首次扫码路径**：用临时空白资料确认过，未登录时页面会跳到 `/login`；窗口停在 `/login` 时面板只轮询、不开后台标签页。但“新账号从扫码到自动绑定”这一整条还没有用真实的第二个账号走过。
- 旧的 `src/adapters/xhs.mjs`（只有 fixture 的契约适配器）不在实际运行路径上；运行路径是 `xhs-live.mjs`。
- **数据来源**：采集时在该账号自己的 Chrome 里开一个后台标签页，打开小红书创作中心页面，只记录页面自己发出的接口响应。不伪造请求，不读取 Cookie，也不执行页面脚本。实现见 `src/transports/cdp-capture.mjs` 和 `src/adapters/xhs-live.mjs`。
  - 身份来源：`/api/galaxy/user/info`。只保留 userId、昵称和小红书号；接口还会返回手机号，这个字段直接丢弃，不存储。
  - 粉丝总数：`/api/galaxy/creator/home/personal_info` 里的 fans_count。
  - 每日指标：`/api/galaxy/v2/creator/datacenter/account/base` 中 `thirty` 里的按日列表：
    发布作品数=publish_note_num_list（图文+视频），曝光=impl_count_list，浏览=view_list（平台口径为“观看”），点赞=like_list，净涨粉=net_rise_fans_count_list，新增粉丝=rise_fans_list。
  - 日期是北京时间自然日（时间戳 = 北京时间 0 点）。平台按天更新，最新一天通常是昨天，今天显示“暂无数据”。
  - **注意**：这台 Mac 的系统时区是 America/Los_Angeles，小红书网页按本机时区显示日期，所以页面上的日期会比面板早一天。面板统一用北京时间，以面板为准。
- **防串号**：每个账号使用独立的浏览器资料、调试端口和会话。采集前后各核对一次身份，数据样本里的 userId 必须等于已绑定的 ID，任何一处不一致都不写入。同一个平台账号不能绑定到第二张卡片（`identity_taken`）。已绑定的卡片如果读到别的身份，会拒绝（`identity_mismatch`）。
- **修复**：面板关闭窗口时用 SIGTERM，会留下 Chrome 的过期 SingletonLock，导致下次无法登录。现在锁文件指向本机、而且对应进程已经不存在时，判定为过期锁，允许启动；进程还在的锁照旧拒绝。
- **未完成 / 不可用**：
  - 定时自动采集：未做，目前需要打开账号窗口后由面板触发。
  - 超过 30 天的历史：数据中心接口只给近 7 天和近 30 天；更早的日期显示“暂无数据”，要靠以后定期采集逐步积累。
  - 作品明细：未接入。
  - 发布：本面板不含任何发布功能。

## 2026-11-19 第四轮：在别的电脑上加账号、减账号、看数据

## 2026-11-19 第三轮：每日定时采集
- `src/scheduler.mjs`：每天北京时间 12:30 之后（可用环境变量 `MAITIAN_COLLECT_AT` 修改；按北京时间计算，与本机时区无关），面板服务每分钟检查一次，到点后执行当天这一轮。每天只运行一次，状态保存在 `data/schedule.json`（权限 600），重启后不会重复运行。如果错过了时间（比如电脑睡眠、服务没开），下次服务运行时会补跑。
- 一次只处理一个账号：打开该账号的专用窗口 → 等待身份核验（最多 45 秒）→ 采集 → 关闭窗口，然后处理下一个。只采集已绑定身份、而且平台已开放采集的账号。
- 你开着任何账号窗口时，定时运行会推迟，等窗口关闭后再跑；“立即全部采集”按钮这时会提示你先关窗口。
- 单个账号失败（比如登录失效）只记录原因，卡片上会提示“需要重新扫码”，其他账号照常采集；每个打开过的窗口都会关闭。
- 修复：读取器返回“尚未核验”（页面还在加载或停在登录页）时，后端原来直接抛错，现在改为如实返回，让调用方可以继续等待。之前手动登录时，前端会反复查询，所以没暴露这个问题；定时采集的首轮实测发现了它。
- 实测：“立即全部采集”逐个跑完 3 个账号，用时约 55 秒，全部成功；窗口全部关闭，没有残留进程。
- 前提：面板服务必须在运行。现已设为开机自动启动，见上文。
- 测试 175 项全部通过（新增 `test/scheduler.test.mjs`）。

# 历史：麦田多账号隔离原型

## 范围
- 与现用 `maitian-local-20261117` 完全分开；未导入任何真实数据库/账号/作品。
- 只有数据模型与调度租约核心，无网页、无浏览器启动、无登录或发布方法。
- 用户规模：小红书 8、抖音 5、视频号 3，共 16 个，注册表不限此数量。

## 已验证
11 项 Node 内置测试：16 账号独立资料路径、同平台同日数据隔离、统一合计、无数据不伪装为零、账号身份不符拒写、重复身份与路径穿越拦截、历史回填不覆盖实测、作品指标外键隔离、输入校验、单 worker 租约、过期租约恢复及数据库文件权限。

## 生产实施建议
1. **账号工作区独立**：每个账号独立 Chromium profile、数据库、配置、日志、截图/导出/项目目录；采用每账号 `MAITIAN_CONFIG`、`MAITIAN_DB`。不要复制当前登录态、不要在已有 profile 内切号。
2. **中央目录与汇总库**：本原型账号注册表与 account_id 维度的数据表用于汇总层，工作进程仍用独立库。采集结果带 platform_user_id 与来源时间；采集前从当前平台核对身份，发现错号立刻停止，不能只相信用户输入标签。
3. **资源预算**：当前 M2 / 8 GB，默认全局一个采集 worker，按需启动一个账号 Chrome，采完释放连接、确认子进程退出后再换下一账号。不要同时启动 16 个 Chrome。两 worker 只能在实际内存验证后启用。
4. **租约不是进程隔离**：本原型 claim/release 仅验证调度锁。租约过期后，生产 supervisor 必须确认或终止其自有旧 worker/Chrome 才能回收；不得杀用户日常浏览器。PID、进程启动时间、profile 三者需匹配。否则旧进程仍活着会突破并发限制。
5. **bridge 不可混用**：当前插件 bridge 单全局队列、端口硬编码，多个 profile 不可共享。优先 direct 采集，不装发布扩展；如后续确需插件，必须为每账号单独 bridge 端口/秘密/Origin/扩展设置与输出目录。
6. **统一面板**：账号卡片/平台筛选/更新时间/登录状态/错误原因；总粉丝标明各账号最新样本（可能不同日）且不是去重人数。无数据显示未采集，不显示真零。另做同一日期可比口径。
7. **仅数据版默认**：不实现上传、发布、自动提交入口。以后发布功能单独授权，不沿用上游自动发布默认值。
8. **迁移方式**：现有数据库先只读备份，确定实际小红书平台账号ID，经用户确认后导入开发副本并核对日期/数量/校验和。绝不直接更改现用库、冒充归属或覆盖历史。
9. **许可**：主仓 MIT、publisher Apache-2.0；复用时保留相应 LICENSE/NOTICE（若存在）与修改说明。原型当前未复制上游源码。
